{{ icon('shield') }} The basics

{% call q('What is this portal?') %}

A small Public Key Infrastructure (PKI) for VIT. Students and faculty request digital certificates, a Registration Authority (RA) checks who they are, and the Issuing CA signs the certificates. Anyone can then check a certificate, or a file signed with one, against the VIT Root CA.

{% endcall %} {% call q('What is a digital certificate?') %}

A small signed file that binds a public key to a person or a server: "this key belongs to Asha Rao, VIT, registration number 21BCE0001". The CA's signature on it is what makes others believe that statement. It also says what the key may be used for and until when.

{% endcall %} {% call q('Why are there two CAs, a Root CA and an Issuing CA?') %}

The Root CA is the anchor everyone trusts, so its private key is kept offline and used only once: to sign the Issuing CA's certificate. The Issuing CA is online and signs the everyday certificates. If the online CA were ever compromised, it could be replaced without changing the root that everyone trusts.

{% endcall %} {% call q('What does the RA do?') %}

The Registration Authority checks the applicant's identity, for example against the VIT ID card, and then approves or rejects the request. It never signs anything itself: on approval, the Issuing CA signs.

{{ icon('upload') }} Requesting a certificate

{% call q('What is a CSR, and how do I make one?') %}

A certificate signing request: your public key, signed with your private key. Sending it proves you hold the key without ever revealing it. With OpenSSL (Git Bash):

openssl req -new -newkey rsa:2048 -nodes -keyout my.key -out my.csr -subj "/CN=me"

For code signing use rsa:3072. Or run python scripts/make_sample_csrs.py and pick a ready-made file from demo_work/.

{% endcall %} {% call q('Should I upload a CSR or use demo mode?') %}

Uploading a CSR is the real way: your private key never leaves your computer. Demo mode lets the server create the key for you and hand it over in a password-protected .p12 file. It is convenient for a demonstration, but in a real PKI nobody but you should ever have your private key.

{% endcall %} {% call q('Why does my certificate not show the name I put in my CSR?') %}

On purpose. The CA ignores the name and any extras requested inside a CSR, and uses only its public key. The certificate carries the details you typed in the form, which the RA checks against your ID, and every other field comes from the certificate type. Otherwise anyone could ask for a certificate in someone else's name.

{% endcall %} {% call q('I lost my tracking ID. What now?') %}

The ID is random, so it cannot be looked up from your name. Submit a new request; the RA can reject the old one.

{% endcall %} {% call q('How long does approval take?') %}

Until an RA officer reviews it. Your status page shows "Waiting for the RA" until then, and changes to approved (with downloads) or rejected (with the reason).

{% endcall %}

{{ icon('download') }} Downloading and keys

{% call q('What are cert.pem, chain.pem and cert.p12?') %}

cert.pem is your certificate. chain.pem holds the Issuing CA and Root CA certificates that vouch for it. cert.p12 (demo mode only) contains your private key, your certificate and the chain, locked with a password. Check your certificate with openssl verify -CAfile root-ca.crt -untrusted chain.pem cert.pem.

{% endcall %} {% call q('I lost the .p12 password. Can it be shown again?') %}

No. It is shown once and then deleted from the server, so nobody, not even the RA, can read it later. Ask the RA to revoke that certificate and submit a new request.

{% endcall %} {% call q('My private key may have leaked. What should I do?') %}

Tell the RA straight away so the certificate is revoked with the reason keyCompromise. From that moment every verifier rejects it, even though it has not expired.

{% endcall %}

{{ icon('pen') }} Signing and verifying files

{% call q('What does a signature on a file prove?') %}

Two things: the file has not changed by a single byte since it was signed, and it was signed with the private key of a named person whose certificate the VIT CA issued. Because only that person holds the key, they cannot easily deny having signed it (non-repudiation).

{% endcall %} {% call q('Which certificate can sign files?') %}

Only a Code and document signing certificate. Others are refused when you sign, and fail check 4 when someone verifies.

{% endcall %} {% call q('What are the five checks on the verify page?') %}
  1. File hash matchesthe file is exactly the one that was signed.
  2. Signature is validthe signature was made with the key in the signer's certificate.
  3. Chains to the VIT Root CAsigner → Issuing CA → Root, every link checked.
  4. Code-signing, valid when signedthe right kind of certificate, valid at the signing time.
  5. Not revokednot on the current revocation list signed by the CA.

The result is VALID only when all five pass.

{% endcall %} {% call q('I changed nothing, but now the signature is NOT VALID. Why?') %}

Most likely the signer's certificate has been revoked: check 5 fails. A revoked certificate is never accepted, even for files signed before the revocation, because the signing time in the .sig.json is only the signer's own claim.

{% endcall %} {% call q('Can I verify without this website?') %}

Yes: python tools/verify_file.py --file report.pdf runs the same five checks, and every check can also be done by hand with OpenSSL (see docs/VERIFY_WITH_OPENSSL.md).

{% endcall %}

{{ icon('inbox') }} RA and revocation

{% call q('What happens when a certificate is revoked?') %}

It is marked revoked with a reason, and the Issuing CA immediately signs a new certificate revocation list (CRL) with the next CRL number, published at /crl.pem. The OCSP responder and the status API answer "revoked" from then on.

{% endcall %} {% call q('Can a revocation be undone?') %}

No. Revocation is permanent. If it was a mistake, the person requests a new certificate.

{% endcall %} {% call q('What is the difference between a CRL and OCSP?') %}

A CRL is the whole list of revoked certificates, signed by the CA and valid for 7 days, which verifiers download. OCSP answers about one certificate at a time ("good", "revoked" or "unknown") with a fresh signed reply.

{% endcall %} {% call q('Why is there no login for the RA pages?') %}

It is a shortcut for the demonstration, which is also why the portal only listens on this computer (127.0.0.1). A real RA would sign in with multi-factor authentication, and every decision would be recorded under that person's name.

{% endcall %}

{{ icon('alert') }} Problems and messages

{% call q('"Setup needed: the CA does not exist yet."') %}

The Root CA and Issuing CA have not been created. Set ROOT_CA_PASS and ISSUING_CA_PASS, run python scripts/bootstrap_ca.py, then restart the portal.

{% endcall %} {% call q('"The Issuing CA key is locked."') %}

The portal cannot unlock the CA's private key. Set ISSUING_CA_PASS in the terminal that runs python run.py and restart it.

{% endcall %} {% call q('"RSA key too small" or "needs an EC P-256 key"') %}

Your key does not fit the certificate type: student login and faculty e-mail need RSA of at least 2048 bits, code signing at least 3072 bits, and a TLS server an EC P-256 key. Make a new CSR with the right key.

{% endcall %} {% call q('"the CSR signature is invalid"') %}

The CSR was damaged or altered after it was made, so it no longer proves you hold the key. Create it again.

{% endcall %} {% call q('"choose ONE: upload a CSR, or tick demo mode"') %}

Use either your own CSR or demo mode, not both (and not neither).

{% endcall %} {% call q('"could not open the .p12 file: wrong password"') %}

The password does not match the .p12, or the file is not a .p12. Passwords are case-sensitive.

{% endcall %} {% call q('Is this portal safe to use for real certificates?') %}

No. It is a teaching demo. Several parts are deliberately simplified, such as no RA login, server-side keys in demo mode and the CA key in memory; docs/SECURITY_NOTES.md lists each one and what a production CA does instead.

{% endcall %}
